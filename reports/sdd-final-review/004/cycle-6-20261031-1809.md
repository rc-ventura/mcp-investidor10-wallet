**Medium / Low (non-blocking in the Security Engineer's grading):**
- **MEDIUM, A01/A02/A09 (privacy-mode bypass chain). The wallet ID reaches the model in every upstream error message.** This is the ID that ADR-0004 (amendment) and `docs/PRIVACY.md` call "a credential". Reproduced: a 404 returned `Investidor10 API returned HTTP 404 for /summary/metrics/<ID> — check WALLET_ID …` through `get_wallet_summary`. It goes to the model as a normal tool result, so `mask_error_details` does not apply.
  - Where: `wallet_client.py:83, 195, 243, 257, 263, 274, 283` all interpolate `{path}`, and `path` contains `wallet_id` (requests are built at `wallet_client.py:228`).
  - Why it matters: if the client gives the agent any web-fetch capability, or if upstream text prompt-injects the model, the ID can read raw amounts from the public API. That defeats `WALLET_MASK_VALUES`.
  - History: cycles 1 and 2 recorded it as LOW and "accepted". None of the five resolution tables tracks it.
  - Fix: redact `wallet_id` from the `path` used in messages, e.g. replace it with `<wallet>`.
- **LOW, A04/A05. An upstream JSON nested a few hundred levels deep raises `RecursionError`, which is not caught.** `wallet_client.py:252-254` catches only `ValueError`.
  - Reproduced: a 100k-deep body (well under the 10 MB cap) makes `get_wallet_summary` and `get_asset_quote` return a generic masked tool error instead of `unexpected_format`.
  - It also makes the whole `get_session_context` fail (`is_error` true, no memory returned). `server.py:438` catches only `SourceError`, so one poisoned quote response kills the session bootstrap.
  - Reaching it needs a compromised host or a MITM via `HTTPS_PROXY` (httpx honours proxy env vars), which is outside the ADR-0004 boundary.
  - The lesson `recursionerror_nao_e_valueerror` was applied only to `memory_store.py:275`. Fix: add `RecursionError` to the except at line 254.
- **LOW, A04. `get_positions` is bounded only loosely.** `wallet_client.py:354-396` caps pages at 400 and each body at 10 MB, but does not cap rows per page to the requested `length=50`. A hostile upstream could push worst-case memory into the gigabytes, and the merged result is then cached. Code-read only, not reproduced at scale.
- **LOW, A04. Alert, collection and text sizes are unbounded.**
  - Counts and free-text length have no cap (`memory_store.py:599`, `add`), and `.log` has no rotation (documented in ADR-0004).
  - `get_session_context` makes a serial quote fetch with a 20 s timeout for each unique alert ticker; this is deferred in `ROADMAP.md:309`.
  - A huge `memory.json` would raise `MemoryError`, which `_reload` does not catch. That is the open ADR-0002 wording item.
- **LOW, A05. Memory error payloads include the absolute path of the memory file.** These go to the model verbatim (`memory_store.py:169,178,352,411` via `memory_error_payload`), which exposes the home directory and username. `_memory_or_param_error` also returns `str(exc)` for any `ValueError`.
- **LOW, A08. In `release.yml` the smoke test runs in the same job that holds `id-token: write`.** `pip install dist/*.whl` resolves transitive dependencies unpinned and executes them. A compromised transitive package could mint the OIDC token for the PyPI publish. Splitting build/smoke and publish into separate jobs, with `id-token` only on publish, would close it.
- **LOW, A08. `ci.yml` has no `permissions:` block** (grep returns 0). Add `contents: read`.
- **LOW, A08. The installer installs the plugin from an unpinned GitHub source.** Marketplace, `#plugin` branch and gemini extension URL all track the default branch (`installer/clients.py`). The plugin ships shell hooks, but the hooks themselves are clean: all quoted, static output, no injection found.
- **LOW, A06. `uvx mcp-investidor10-wallet@0.3.0` resolves transitive dependencies without `uv.lock`**, so end users do not get the audited lock.
- **LOW, robustness (installer).**
  - `subprocess.TimeoutExpired` or `FileNotFoundError` from `_run` is not handled (`installer/clients.py:13`), so the installer dies with a traceback.
  - Functional bug at `installer/cli.py:150`: `zip(detected, session.outcomes)` pairs the wrong adapter and outcome when `--clients` names an absent client, because the absent outcomes are appended first. A plugin can then install for a client whose registration failed. This is not a security issue.

### Architecture Assessment
- **Overall:** The architecture is sound and consistent with the ADRs. The layers are clear: `wallet_client` (transport, cache, validation), `memory_store` (persistence, lock, changelog), `privacy` (allowlist), `server` (tools, middleware, envelope) and `installer`. The cycle-5 blocking item (max-`total` adoption) is genuinely fixed and tested. Gates are green (449 tests, about 97% coverage, ruff clean, `pip-audit` clean). Memory-store robustness (lock, read-only latch, corruption path, changelog before save) is well built. There are no HIGH or MEDIUM defects in the code as built.
- **Complexity:** `memory_store.py` has accumulated a lot of defensive code over five cycles. It is justified by ADR-0002 and ADR-0013, but it is the file to watch.
- **Systemic weakness, one cause:** untrusted or sensitive data is handled per call site, not at a single boundary.
  - Every `SourceError` message builds its own text from `path`, so the redaction decision is spread over 7 sites. It should be made once in `request()`: derive a display path with the wallet ID replaced by `<wallet>`, and use that everywhere.
  - The same pattern appears in `memory_error_payload`, which returns `str(exc)`; that text contains the absolute memory path (username and home directory) to the model. This is advisory and the same fix class.
- **SOLID:** `request()` is a long function that fetches, classifies, parses and validates. It is acceptable at this size, and extracting a message-building helper is the natural fix. The `get_session_context` quote loop is a mild robustness smell: one ticker's unexpected failure aborts the whole bootstrap. Fixing the `RecursionError` at the source closes the known case, and a broader per-ticker `except` is optional.
- **Installer:** `cli.py:150` is a correctness bug caused by an implicit positional coupling between two lists (`detected` and `outcomes`). It is narrow: it needs an explicit `--clients` naming an absent client. The effect is that a plugin may be installed for a client whose MCP registration failed. It is not a security issue.
- **Scalability:** Unbounded alert, collection and text sizes, rows per page in `get_positions`, and the serial quote budget are not a single-user problem. They are already documented or deferred (ADR-0002 no-cap, ROADMAP:309). They need a ROADMAP entry, not 0.3.0 code.

### Cross-Report Synthesis
- **Two systemic patterns, not isolated findings.**
  1. *Untrusted or sensitive data crosses the boundary per call site.* The wallet ID in `SourceError` messages, the absolute path in memory payloads and the missed `RecursionError` at the second `json.loads` are the same defect class. The fix pattern is a single construction boundary.
  2. *Resolution tables drifted from reality.* QA found stale or wrong rows (T054 pending on PR #9 though it is merged and `main@5e0a422` is CI-green, 10/10 jobs; the `.lock` row; about eight line citations). Security found a risk that never entered any table (the wallet ID in errors, recorded as LOW "accepted" in cycles 1 and 2 and then dropped). The cycle process tracked what the reports said last, not what was still true in the code. Mandatory item 3 repairs this once for the release record.
- **The ID in errors: decision.**
  - The finding is real and confirmed by reading the code. Security rated it MEDIUM and QA did not mention it, which is inconsistent. I rate it MEDIUM and make it a 0.3.0 blocker.
  - Why it is a blocker and not an advisory: 0.3.0 is the privacy-mode release, and ADR-0004 and `docs/PRIVACY.md` explicitly call the ID a password-grade credential. A release whose headline feature promises to keep sensitive data from the model, while the same server sends the credential to the model on every upstream 4xx/5xx or malformed response, contradicts its own documented position. Combined with any web-fetch tool in the client, or prompt injection through upstream text, the ID defeats `WALLET_MASK_VALUES` outright.
  - The error path is not rare: a private or deleted wallet, or a 404, triggers it in normal use.
  - The fix is small and low risk (one display path in `request()`, one regression test). PyPI publication cannot be undone, and the ID, once in a transcript, cannot be retracted. The cost asymmetry favours fixing before the tag.
  - What stays an advisory: the ID on stderr for the operator and on argv/client configs (the operator owns that, per ADR-0009 and ADR-0004).
- **Disagreements and corrections between reports.**
  - `.lock` `O_NOFOLLOW`: the cycle-4 evidence is wrong; QA and Security agree it is mitigated by the pin.
  - Devin's "MEDIUM" for `record_decision_outcome` overwriting a terminal outcome: I agree with QA's LOW (design). No spec forbids it, and alerts differ by design.
  - `cancel_price_alert(alert_id=true)` coerces to 1: LOW, but trivial. Use strict int in the tool parameter type if touched.
- **Release hygiene:**
  - The `release.yml` job runs `pip install` of unpinned transitive dependencies, with `id-token: write` workflow-wide. This is a genuine supply-chain pattern. The pipeline can only be tested by tagging, so I do not want an untested restructuring right before an irreversible publish. Schedule the job split (build/smoke without `id-token`, publish job with it) for 0.3.1 with a rehearsal against TestPyPI or a pre-release tag. Add `permissions: contents: read` to `ci.yml` now, since it is trivial and safe.
  - `uvx` consumers do not get `uv.lock` transitive pinning. This is accepted by design (ADR-0011) and documented as such.
