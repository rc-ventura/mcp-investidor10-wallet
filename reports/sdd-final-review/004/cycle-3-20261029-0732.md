## Tech Leader Verdict

### Architecture Assessment

The spec-004 hardening is architecturally sound and ADR-faithful at the design level: single funnel for locking (`_locked()`), single emission point for errors (`ErrorSignalMiddleware`), fail-closed privacy allowlist applied post-cache, three-phase `get_session_context` never holding the lock across network I/O (correct per ADR-0013 §4). Modules stay cohesive (`bootstrap` = operator-facing lifecycle, `wallet_client` = sole upstream owner, `memory_store` = sole persistence owner, `privacy` = pure masking). Complexity is proportionate to a single-user stdio server; nothing new violates layering, and `fastmcp==4.1.2`/`filelock==4.2.4` pins plus the `audit` CI job satisfy the amended ADR-0001 dependency policy.

Three **systemic** weaknesses, not isolated bugs:

1. **File-open hardening applied per-callsite instead of via one primitive.** `.log` gets `O_NOFOLLOW`+`fchmod` (memory_store.py:330-336), `.lock` gets kernel-lock `O_NOFOLLOW` — but `_reload` (memory_store.py:204) and `_backup_corrupt_file` (:261) still `open(self.path)` following symlinks. This is the exact pattern the cycle-2 verdict already predicted (`_open_private` helper) — Security's TOCTOU MEDIUM and QA's WALLET_MEMORY_PATH symlink-detach LOW are the same root cause on the main file.
2. **Two clocks for one freshness decision.** `request()`/`_stale_envelope` use `time.monotonic()` (wallet_client.py:187, 213); `is_stale()` recomputes age from wall-clock `fetched_at` (:173-177). ADR-0017 claims clock skew errs "sempre em favor de não disparar" — false for a backward step: negative/shrunken age → looks fresh → **terminal** alert fires on stale price. The fix must use the client's own monotonic cache age (provenance), not another wall-clock reading.
3. **Errno classification conflates transient with unsupported.** `UNSUPPORTED_LOCK_ERRNOS` (:29-33) lumps `ENOLCK` (kernel lock table exhaustion — transient-capable) with `ENOSYS`/`EOPNOTSUPP`, and `_acquire` latches `read_only` **permanently** (:162) — a transient failure disables writes until restart. ADR-0013 §5's read-only semantics only justify "filesystem does not support locking."

Structural debt worth noting: `save()` public at depth 0 bypasses read-modify-write (:342-347, currently only reachable via correct in-tree paths), and `MemoryStore._depth` as a process-global counter + `thread_local=False` lock is a latent landmine if any caller ever enters from a second thread — second thread skips acquire *and* reload, mutating `self.data` unsynchronized while the first thread's exit releases the OS lock under it.

### Cross-Report Synthesis

Every MEDIUM is cheap: the thread-safety guard is ~3 lines (`threading.local` depth → second thread blocks → `MemoryBusyError`, already the designed failure); `is_stale` provenance-check is bounded by the 256-entry cache; ENOLCK split is a one-set change; O_NOFOLLOW per-read is the helper already written for `.log`; pagination bound reuses the existing `truncated` flag. Remaining non-code items (avg_price, wallet ID, T048/T054/T055) are maintainer/CI actions, not review findings.
