## Bugs Found

| Severity | Description | Location |
|----------|-------------|----------|
| MEDIUM | Alert evaluation uses stale-cache quotes. On 5xx or transport error, `request()` serves cache up to 24h old with `cached=True`. `get_session_context` reads only `data` and ignores `cached`/`fetched_at`. Because `triggered` is terminal, a stale price can permanently fire an alert and be reported as the "current price". Failure scenario: PETR4 cached at T0; at T+2h the source returns 503; session start evaluates the alert against the stale price and marks it triggered. | server.py:406-411; wallet_client.py:139-154, 193-195 |
| MEDIUM | Deleting `memory.json` silently resets memory. `_reload` treats a missing file as empty and writes it immediately. Verified with `probe_delete.py`: a saved rule disappears after `os.remove`, and the file is recreated as an empty store. Only `memory.json.log` keeps the history. | memory_store.py:181-189 |
| MEDIUM | Positions merge can silently truncate. When the source ignores `start`, the loop stops with fewer rows than `total`. `merged["total"] = len(rows)` then overwrites the declared total, so the model cannot detect incompleteness. This follows the documented lesson's design, but it conflicts with the 100%-of-assets criterion. | wallet_client.py:322-331 (esp. 330) |
| MEDIUM | Unexpected-exception details are not sanitized. FastMCP's `mask_error_details` defaults to `False` (`fastmcp/settings.py:205-217`) and `FastMCP(...)` never sets it. The spec edge case requires sanitized detail plus a server-side log. Failure scenario: an internal bug raises `KeyError('data')` and the client receives that raw text. | server.py:22, 25-51 |
| LOW | `cancel_price_alert` on a non-active alert raises `ValueError`, which maps to `invalid_params`. That is a state conflict, not an argument error, and the next-action text "check the schema" is misleading. | memory_store.py:557-560; server.py:320-323 |
| LOW | Validation errors do not name the offending argument (weakens FR-023). | server.py:35-38 |
| LOW | Retry budget is 6 `os.replace` attempts (5 sleeps plus a final one) versus the contract's "até 5 tentativas". | memory_store.py:28, 235-242 |
| LOW | Envelope `cached`/`fetched_at` for a multi-page positions merge reflect only the last page, so mixed freshness is reported as one. | wallet_client.py:307, 328-331 |
| LOW | Non-dict position rows are dropped silently when masking, with no `omitted` marker. | privacy.py:85-86 |

## Tech Leader Verdict

Verified against code and by two probes (scratchpad `probe.py`). Repo not modified.

### Architecture Assessment
- **Structure:** Spec 004 fits the architecture of ADR-0001. `MemoryStore` has one reload-under-lock path, `_locked()`, and every public read/write goes through it. That path is re-entrant with a depth counter (`memory_store.py:157-174`). Error signalling lives in a single `ErrorSignalMiddleware` (`server.py:25-51`). Privacy masking lives in a single module (`privacy.py`).
- **SOLID:** `MemoryStore` carries lock, load, backup, atomic write and changelog in one class. At ~600 lines for a single-user server that is acceptable. No split requested.
- **Robustness:** The lock, depth reset on exception, corrupt-file backup and 0600 temp file are sound.
- **Defects:** The defects are small and local. They are two places where a hardening requirement was only half applied: the lock file mode (verified 0644) and unexpected-exception sanitization. Neither is a design flaw.
- **Complexity:** Complexity is proportionate. The thread-safety remarks (`_depth`, `thread_local=False`) are not reachable, because all tools run on the asyncio loop thread.

### ADR Compliance
- ✅ ADR-0001 platform and storage: Compliant. `filelock` is a pinned dependency.
- ✅ ADR-0002 persistence and alerts: Compliant. The single atomic save and terminal-trigger semantics are intact. The stale-quote and missing-file concerns are pre-existing (see table).
- ✅ ADR-0003 stale-cache and pagination: Compliant. The stale quote path and `total = len(rows)` are exactly what it prescribes: 24h bound, disclosure kept, honest count.
- ❌ ADR-0004 threat model: **Documentation drift introduced by 004.**
  - §4 says nothing is written to logs, but the changelog now stores full before/after copies of theses and decisions (`memory_store.py:269-290`).
