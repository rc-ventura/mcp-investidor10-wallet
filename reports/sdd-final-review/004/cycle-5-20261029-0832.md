## Tech Leader Verdict

### Architecture Assessment

**Verified the QA MEDIUM myself — it is real and blocking.** The `total is None` gate at `wallet_client.py:387` adopts a declared `total` only from the *first* page that declares one. The rows-exceed-total invalidation at `:401-405` does **not** neutralize a growing later total — it only fires when collected rows exceed the *already-adopted* counter, and a larger later declaration is never adopted in the first place. Reproduced: page1 `total=100` (50 rows) + page2 `total=200` (50 new rows) → `len(rows)=100 >= total=100` → break → `truncated = False` on a list the source itself declares incomplete. Identical fail-open shape to the cycle-4 finding, one level deeper: the counter is validated for *shape*, not for *cross-page consistency*. `max`-adoption fixes it cleanly: the largest declared total is the most demanding completeness claim; if rows ever exceed it, the existing `:401-405` invalidation discards it. One line + one regression test.

**Verified the QA LOW `_seen_file` gap — confirmed.** `memory_store.py:324`/`:367` set the latch only on schema-valid load or successful write. A rejected file (corrupt `:289-294`/`:319-321`, or `version > SCHEMA_VERSION` `:304-310`) leaves it `False`; mid-session deletion then takes the first-run branch `:281-287` → writes an empty store + `available=True`, defeating the designed "vanished" degradation. For future-version files (no backup per ADR-0002 §2) the content is lost outright. Fix is `self._seen_file = True` immediately after a successful `_read_file()` at `:266`.

**BOM (`:267`), last-page envelope inheritance (`:412`, `:419`), missing `months` upper bound (`:546-552`), serial quote loop (`server.py:425-447`) — all confirmed as reported.** `check_months` has no ceiling (`months=10**9` passes); the quote loop is sequential awaits at up to `REQUEST_TIMEOUT_SECONDS=20` each. Neither the quote budget nor the `months` bound was fixed **or** recorded as deferred — the ROADMAP "Pendências da revisão final" section (`docs/ROADMAP.md:237-294`) is the established deferral ledger and neither appears there. That is a process violation even if the technical severity is LOW.

Architecture overall remains sound: clean layering, single source of truth (`TICKER_PATTERN`), fail-closed privacy allowlist (`privacy.py:78-84` — ADR-0015 condition closed), degradation semantics consistent with ADR-0002, passthrough envelope per ADR-0007, dual error signal per ADR-0014. No systemic design flaw — the residual is one incompletely-applied guard.
