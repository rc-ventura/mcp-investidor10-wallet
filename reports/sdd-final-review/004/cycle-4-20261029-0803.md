## Tech Leader Verdict

### Architecture Assessment

The architecture remains coherent and faithful to its recorded decisions. I read all 17 ADRs, all 12 learning lessons, and the flagged code paths. The layering is clean: `bootstrap.py` (operator boundary, PT-BR), `wallet_client.py` (untrusted remote boundary), `memory_store.py` (untrusted local-file boundary), `privacy.py` (LLM-provider boundary), `server.py` (thin tool adapters + dual error signal). SOLID posture is good — single-responsibility modules, closed error-code set (12), fail-closed defaults everywhere.

However, cycle 4's two new MEDIUMs reveal a **systemic pattern**, not isolated bugs: the hardening correctly bounded *expected* failure shapes but under-specified *parser/adversarial* shapes on the two trust boundaries.

1. **`memory_store.py:243-266` — confirmed.** `json.loads`/`json.dumps` on deeply-nested input raises `RecursionError` (a `RuntimeError`, not `ValueError`). It escapes `except (ValueError, UnicodeDecodeError)`, bypasses `_backup_corrupt_file`, leaves `available=True`, and propagates as a masked generic error — permanently, on every op, with no forensic backup. This defeats the entire ADR-0002 containment design. Locks release correctly in `_locked` (no deadlock), but the store is a zombie. The remote boundary got `MAX_RESPONSE_BYTES` and capped reads (`wallet_client.py:30,85-102`); the local boundary got neither a size cap (Security A04) nor a parser-depth guard — an asymmetry worth one decision line.
2. **`wallet_client.py:382-408` — confirmed.** `type(page.get("total")) is int` adopts `total=0`/negative/under-collected declarations. `len(rows) >= total` then breaks after page 1 while `len(rows) < total` is False → `truncated=False` — silently partial, exactly what `truncated` exists to flag. The cycle-3 guards (dedupe, progress, `MAX_POSITION_PAGES`) protect the *merge*; nothing validates the *declared counter itself* — the same "don't trust source-declared state" lesson applied one level too shallow.

Docs: `docs/ROADMAP.md:404` (actual line) still contains the real second-wallet ID — confirmed, same disclosure class as the scrubbed ones. `tasks.md:170,201,279` still say "11 códigos/11 linhas" — drift confirmed (T029 itself notes the emenda to 12).
