Verified OK (no finding):
- **A01 / A05, local page.**
  - Binds to `127.0.0.1` on an ephemeral port; `allow_reuse_address` is off.
  - Host must be exactly `127.0.0.1:port`; `localhost` and a foreign Host both get 403.
  - POST requires an exact `Origin`; missing, `null` and foreign origins get 403, and an invalid token gets 403.
  - Token is 256-bit `secrets.token_urlsafe` with `compare_digest`; a duplicate `t=` parameter gets 403.
  - Body capped at 64 KB, `log_message` is silenced, other methods return 501.
  - Response headers include a CSP with nonce, `frame-ancestors 'none'`, `base-uri 'none'`, `nosniff`, `no-store` and `X-Frame-Options: DENY`.
  - `Referrer-Policy: same-origin` is deliberate and matches the learning lesson.
  - All interpolated values are `html.escape`d.
- **A10 / SSRF.**
  - Link parsing allows only the hosts `investidor10.com.br` and `www.investidor10.com.br` over https, port 443 or none, and rejects userinfo.
  - Wallet ID must be `[0-9]+` and the credential `[A-Za-z0-9_-]{1,256}`, so there is no path or query injection.
  - The client uses `follow_redirects=False` and a 10 MB response cap.
  - The credential (`hash` param) is sent only when `base_url == WALLET_PROXY_BASE_URL`, and `_redact` scrubs both the ID and the credential from error paths.
- **A03, subprocess calls.** The installer and doctor use list-form `subprocess.run`, with constant arguments plus `__version__`, and no `shell=True`. The only input-derived values are validated digits or an enum.
- **A03, GitHub Actions script injection.** Untrusted values (`head_ref`, `inputs.tag`, `ref_name`) go through `env:` and are re-validated by regex in the scripts. `${{ }}` is never used inside a `run:` body.
- **Doctor output.** It prints only the id=status summary and boolean "credential present". `sanitize()` masks home, username and the ID and credential. The Claude Desktop config is read through `O_NOFOLLOW` with a size cap and its content is never printed.
- **Workflows, general.**

### Architecture Assessment

- **Alignment with ADRs is strong.**

### Cross-Report Synthesis

- **No Critical or High findings in either report.** The two reviewers converged on the same real defects, which confirms they are not artifacts: the Content-Length Unicode crash, the missing socket timeout, the argv `--link`, and the main-gate and tag-publishing trust boundaries.
- **Two systemic patterns, both small.**
  1. **Trust the platform edge.** The handler reads the body before authenticating and has no timeout; `_run` has no timeout handling; scripts use `\d` and `isdigit()` where `[0-9]` is meant. These are one class: input and process boundaries written for the happy path. The core data paths (config, wallet client, privacy) do not show it, because earlier lessons were applied there. The fix is one 0.4.1 sweep, not a redesign.
  2. **Controls that live in repo settings, not in the repo.** Both Medium release findings are about this. The repo can only declare the intent (ADR-0020 §8). The check is a settings read. In this one-maintainer model the real controls are the rulesets, the `pypi` reviewer, and the maintainer's own account security. The finding is therefore that the ADR text and the actual settings drifted apart. The residual risk is a compromised maintainer account, which is out of scope under ADR-0004.
- **Which Mediums are real in the single-maintainer personal-use model (ADR-0004):**
  - **QA `_run` timeout:** real, but a usability and diagnostic bug. A slow `claude mcp list` makes `doctor` print a traceback instead of the sanitized report it exists to produce. Fix it in 0.4.1.
  - **Security local-page DoS:** much weaker than "Medium" here. The port is loopback, ephemeral and open at most 10 minutes. Nothing leaks and no wallet data is at stake. The worst case is a stalled thread until the process exits. The Unicode `Content-Length` traceback is cosmetic. Treat it as Low and fix it cheaply in 0.4.1.
  - **`main-gate` runs PR-supplied code:** true as stated, but the attacker would need write access to the repo, and that is the maintainer. It is a documentation point (ADR-0020 amendment), not a vulnerability here.
  - **Any `v*` tag publishes:** real as a configuration drift. The environment reviewer already protects against a surprise publish. What is missing is the tag policy that ADR-0020 §8 says exists. It is a 30-second settings change, so it belongs in bucket A.
- **Quality of the release machinery:** v0.4.0 was published through the right pipeline (build, human approval, verify on 3 OS). Only the promotion to `main` and the closing steps remain.
